# LegalMind — Sample Inputs & Outputs

All inputs are synthetic (PDF permits this). Names, cases, parties, and
numbers are fictional. Everything below is committed to the repo so the
system's behaviour is inspectable **without a GPU**.

## Inputs (`data/sample/`)

### Clean legal-style text (5 documents, one per realistic draft type)

| File (txt + pdf) | Draft type | What it exercises |
|---|---|---|
| `doc_1_lease_agreement` | case_fact_summary | Parties, dates, monetary terms |
| `doc_2_court_filing` | case_fact_summary | Multiple defendants, claims, counsel |
| `doc_3_property_deed` | title_review_summary | Ownership chain, encumbrances |
| `doc_4_compliance_notice` | notice_summary | Deadlines, required actions |
| `doc_5_document_checklist` | document_checklist | Present vs missing documents |

Both `data/sample/*.txt` (raw) and `data/sample/pdfs/doc_*.pdf` (PDF-wrapped)
are provided so the text-extraction path is directly testable.

### Messy / degraded scans (25 images — the "messy input" requirement)

`data/sample/images/img_{1..5}_level_{1..5}.png` — five source documents,
each rendered at **five increasing degradation levels** (level 1 = light
noise, level 5 = heavy blur/skew/low-res). `img_N` shares content with
`doc_N`, so OCR output can be checked against the clean text. PDF-wrapped
copies are in `data/sample/pdfs/img_*_level_*.pdf`.

### Expected outputs (`data/sample/expected_outputs/`)

One `*_expected.json` per input with ground-truth structured fields, used by
the evaluation script to score extraction accuracy.

## Outputs (real, committed — `data/processed/`)

Generated by the actual pipeline on this hardware:

| Draft file | Type | Grounding (verified / total) | Exemplars | Rules |
|---|---|---|---|---|
| `draft_doc_b9790d1d5f34_case_fact_summary.json` | case_fact (doc_1 lease) | 6 / 10 | 3 | 3 |
| `draft_doc_3e27ad443cca_title_review_summary.json` | title_review (doc_3 deed) | 13 / 18 | 0* | 3 |
| `draft_doc_6802495c90ea_case_fact_summary.json` | case_fact (doc_2 filing) | see EVALUATION A/B | 3 | 3→6 |

\* 0 exemplars for the deed is correct: exemplar retrieval is **per draft
type**, and all accumulated corrections are `case_fact_summary` — the system
does not leak unrelated corrections across types.

Each draft JSON contains: `content_markdown` (the human-readable draft with
inline `[E1]` citations), `citations` (the `[E]` → evidence map with page +
char span), `firewall_results` / `firewall_summary` (per-claim verification),
`exemplars_used`, `rules_applied`, `confidence_overall`.

## What a generated draft looks like (excerpt, doc_2 court filing)

```markdown
## CASE FACT SUMMARY

### Document Summary
This is a Complaint filed in the District Court of Caldwell County, State of
Thornfield, Case No. CV-2024-08847, brought by Synthex Industrial Partners
Inc. against Norwood Fabrication Group LLC and Gerald P. Norwood individually,
alleging breach of contract, fraud, and unjust enrichment. The complaint was
filed on March 14, 2024, and seeks damages totaling $680,000.00 (compensatory
plus punitive). The plaintiff is represented by Kavanaugh & Ashworth LLP [E1].

### 1. Parties
#### Plaintiffs
- Full legal name: Synthex Industrial Partners Inc. [E1]
- Role description: Plaintiff [E1]
- Represented by (if stated): Kavanaugh & Ashworth LLP [E1]
```

Every factual line carries a `[E1]`-style citation. In the web UI the
verification badge is clickable — it lists each claim as
verified / uncertain / unsupported with the exact evidence snippet, and the
citation "eye" opens the source page image (PDF/scan) or the highlighted
source text span (txt).

## Reproduce

```bash
# 1. seed sample inputs + expected outputs
python scripts/seed_sample_data.py

# 2. start server (see 01_README.md)

# 3. clean text path
curl -X POST http://localhost:7860/api/v1/documents/upload \
  -F file=@data/sample/pdfs/doc_1_lease_agreement.pdf \
  -F draft_type=case_fact_summary

# 4. degraded-scan / OCR path
curl -X POST http://localhost:7860/api/v1/documents/upload \
  -F file=@data/sample/images/img_1_level_4.png \
  -F draft_type=case_fact_summary

# Generated drafts land in data/processed/draft_<id>_<type>.json
# and are viewable at http://localhost:7860/documents/<id>/draft
```
