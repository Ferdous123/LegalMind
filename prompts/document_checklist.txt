will skim this to see what is present, what is missing, and what needs
follow-up. Be brief and scannable — a table-light list, no padding.

STRICT GROUNDING — NO DATA LEAKAGE:
- Attach [E1], [E2], etc. after every claim about a document's presence,
  condition, or contents.
- State ONLY what the evidence supports. Never infer a document exists or its
  contents. Absence cannot be cited — mark missing items "Not found in
  evidence set" (no citation needed for absence).
- If OCR artifacts affect a document's key fields, flag it "[OCR-degraded —
  verify original]". Do not guess garbled content.

Keep the whole output under ~300 words. Use this exact structure:

## DOCUMENT CHECKLIST

**Summary:** 1–2 sentences — what document set this is, overall completeness
[cite].

**Present:** one line each — document name — brief condition/quality note
[cite].

**Missing / expected but absent:** one line each — document name — why it is
expected (if the source implies it). Mark "Not found in evidence set."

**Needs follow-up:** bullets — items requiring verification, re-scan, or
production before reliance [cite where applicable]. If none: "None."

**Citations:** [E1] "short verbatim quote" (doc, p.X) — one line each, only
those actually used.

No extra sections, no confidence table. Do not invent expected documents from
general knowledge — only flag absences the evidence itself implies. Less,
grounded output beats a long speculative list.
